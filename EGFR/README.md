# EGFR Molecular Research

EGFR is a research prototype for exploring human EGFR inhibitor molecules. It accepts molecular SMILES, validates and canonicalizes structures with RDKit, renders a 2D depiction, and calculates common molecular descriptors. It includes an opt-in ChEMBL curation and model-training pipeline for a narrowly defined endpoint: human wild-type EGFR single-protein binding IC50.

> **Research limitation:** downloaded activity data and trained model artifacts are excluded from Git. A clean clone supports structure analysis but will not produce potency predictions until the data are fetched and curated and an eligible model is trained or configured. Any estimate is an exploratory in-vitro IC50-derived result—not clinical efficacy, a treatment recommendation, or a clinically validated prediction.

## What is implemented

- Responsive overview, molecule analyzer, and candidate-ranking workspace.
- SMILES parsing, canonical isomeric SMILES, 2D PNG depiction, and RDKit descriptors: molecular weight, Crippen LogP, TPSA, H-bond donors, and H-bond acceptors.
- ChEMBL data acquisition and transparent curation script for exact IC50 values in nM from high-confidence, single-protein binding assays assigned to human EGFR.
- A scaffold-separated Random Forest training/evaluation pipeline with a mean baseline, calibration partition, held-out test metrics, source manifest, version metadata, and a validation eligibility check.
- An optional, separately-versioned Morgan/Tanimoto applicability screen with calibration-derived structural-support tiers and nearest training neighbors. The tiers describe structural resemblance only; they do not establish activity or prediction accuracy.
- FastAPI `/analyze`, `/predict`, and `/health` endpoints. `/analyze` remains useful without a model; `/predict` returns `503` until an eligible model artifact is created.
- Automated backend unit tests and frontend component tests.

## What is not yet implemented

- No assay dataset or trained artifact is committed. Fetch and review the data, then train locally before predictions become available.
- The candidate workspace accepts user-supplied SMILES for structure analysis and ranks candidates only when the configured model returns real outputs. There is no bundled candidate dataset or persistent candidate storage.
- Assay conditions can vary even within the selected single-protein binding format. Read the curation report and evaluation limitations before interpreting a model.
- No output is clinically validated, suitable for medical decisions, or evidence of therapeutic efficacy.

## Scientific task and data provenance

The fetcher uses the ChEMBL single-protein target `CHEMBL203` (human epidermal growth factor receptor, UniProt `P00533`). It gets assay/activity records from the ChEMBL web services and records the database release, query counts, curation filters, and exclusion counts in a manifest.

The initial task is regression on exact (`=`) IC50 measurements in nM. The curation retains binding assay type `B`, target confidence score 9, single-protein BAO format, no annotated assay variant, no ChEMBL validity comment, no potential-duplicate flag, and RDKit-parseable molecular structures. The label is calculated as `pIC50 = 9 - log10(IC50 in nM)`. Censored values and other endpoints/units are excluded rather than treated as exact IC50 values.

ChEMBL records and derived model outputs retain source IDs and release metadata. Review [data/README.md](./data/README.md) and ChEMBL's [web services publication](https://pmc.ncbi.nlm.nih.gov/articles/PMC4489243/) before reusing or redistributing data. The filters reduce assay mismatch, but do not make results assay-independent.

## Model and evaluation

The initial baseline uses RDKit Morgan fingerprints (radius 2, 2048 bits) and a scikit-learn `RandomForestRegressor`. A training-mean dummy regressor is the baseline. Unique canonical structures are grouped by Bemis–Murcko scaffold so related scaffolds do not cross train, validation, calibration, and test partitions.

The model is eligible for API inference only if its validation MAE is lower than the training-mean baseline's validation MAE. Test metrics are reported separately and are not used in that eligibility decision. The report includes MAE, RMSE, R² when calculable, split sizes, empirical interval coverage/width, dataset hash, and library versions. These are generated by the actual training run; no performance value is claimed in this README.

The displayed empirical interval is based on absolute errors from a scaffold-separated calibration set. It is an exploratory estimate, not a guaranteed prediction interval or a clinical confidence interval. In the current training run, held-out coverage can differ from the nominal calibration level; inspect the generated report. Candidate ordering sorts point estimates only, so overlapping intervals do not establish a meaningful potency difference. Scaffold separation does not prove prospective generalization; inspect the report and model limitations.

Applicability screening is a separate structural-support signal. Build its
training-only reference with `python scripts/build_applicability_reference.py`;
the command reads the existing model, curated dataset, and calibration partition
and writes a new versioned local reference without retraining or replacing the
model. See [model applicability](./docs/model_applicability.md) for thresholds,
provenance, and limitations.

For the recorded comparison of seeded random-compound and scaffold splits,
leakage checks, cluster-bootstrap metric intervals, and the 83.89% interval
undercoverage investigation, see [model evaluation](./docs/model_evaluation.md).
Re-run it with `python scripts/evaluate_splits.py`; this writes a separate
timestamped report and does not replace the baseline model or its metrics.

## Setup

### Prerequisites

- Python 3.11
- Node.js 18+ and npm
- Internet access for the ChEMBL fetch step

### Install Python dependencies

From the project directory:

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-dev.txt
cd ..
```

Runtime dependencies are version-pinned in [backend/requirements.txt](./backend/requirements.txt). Install the dev file to include the test runner.

### Fetch and inspect data

From the project directory, with the backend virtual environment active:

```powershell
python scripts/fetch_chembl.py
```

Generated raw and curated data are written under `data/raw/` and are intentionally excluded from Git. Inspect `chembl_egfr_wt_ic50_manifest.json` and the raw CSV's exclusion reasons before training. The fetch requires ChEMBL API access and may take time because it retrieves assay and activity pages.

### Train and evaluate

```powershell
python scripts/train_efficacy.py
```

The script writes a metrics report in `models/`. It saves a model artifact only when validation beats the mean baseline. No artifact means prediction remains unavailable. Model artifacts are ignored by Git; deployments must supply the artifact explicitly.

### Run the API

From `backend/`:

```powershell
uvicorn app.main:app --reload
```

The API is available at `http://127.0.0.1:8000`; OpenAPI docs are at `/docs`. To use an artifact at a non-default path, set `EGFR_MODEL_PATH` before starting the API:

```powershell
$env:EGFR_MODEL_PATH = "..\models\egfr_wt_ic50.joblib"
uvicorn app.main:app --reload
```

The default model path is `models/egfr_wt_ic50.joblib` at the project root.

### Run the frontend

In another terminal:

```powershell
cd frontend
npm install
Copy-Item .env.example .env
npm run dev
```

Vite proxies `/api` to `http://127.0.0.1:8000` by default. Override `VITE_API_PROXY_TARGET` in `frontend/.env` if needed. For a deployment without a same-origin API proxy, set `VITE_API_BASE_URL` to the public API base URL and configure backend `EGFR_ALLOWED_ORIGINS`.

## API

| Method | Path | Behavior |
|---|---|---|
| `GET` | `/` | API-running message |
| `GET` | `/health` | API health and whether a model artifact is available |
| `POST` | `/analyze` | Validate/canonicalize SMILES, return depiction and descriptors, and include a prediction only if a model artifact exists |
| `POST` | `/predict` | Return endpoint-specific model output when available; otherwise return `503` with the reason |

The request body for both POST routes is `{"smiles": "<SMILES>"}`. The API rejects empty/oversized input and invalid SMILES with `422`. API errors are explicit; no score is substituted when prediction is unavailable.

`EGFR_ALLOWED_ORIGINS` is a comma-separated origin allowlist for direct browser-to-API requests. The backend reads it from the process environment and does not automatically load `.env` files. Never put secrets in `VITE_*` variables; they are browser-visible.

## Tests and build

From the project directory:

```powershell
python -m pytest
cd frontend
npm run test
npm run build
```

Backend tests cover RDKit parsing, descriptors, depiction bytes, fingerprints, ChEMBL curation, model evaluation, applicability screening, and explicit no-model behavior. Frontend component tests cover analyzer and candidate-ranking responses, validation, sorting, applicability status, and unavailable-model states. No scientific performance claim should be added unless it comes from a recorded, reproducible training report.

## Deployment

This repository does not include Docker, Vercel, or Render deployment configuration, so deployment has not been verified. A split Vercel/Render setup is feasible, but requires platform configuration:

- **Frontend (Vercel):** use `frontend/` as the project root, `npm run build` as the build command, and `dist` as the output directory. Set `VITE_API_BASE_URL` to the deployed API base URL and configure an SPA fallback for the React Router routes. The Vite `/api` proxy is for local development; it is not included in the production build.
- **Backend (Render):** use `backend/` as the service root, install from `requirements.txt`, and start with `uvicorn app.main:app --host 0.0.0.0 --port $PORT`. Set `EGFR_ALLOWED_ORIGINS` to the exact deployed frontend origins. Verify RDKit and scikit-learn install successfully in the selected runtime.
- **Model files:** model artifacts and applicability references are excluded from Git. Provide the trusted eligible model artifact and its matching versioned applicability reference through deployment storage, then set `EGFR_MODEL_PATH` and, if needed, `EGFR_APPLICABILITY_REFERENCE_DIR`. Without a model, `/predict` returns `503`; without a matching domain reference, predictions may run but structural support is `unavailable`.

Fetch and train offline; do not download data or train during API startup or per request. This project has no database or persistent candidate history. Complete provider-specific build, startup, health-check, origin, artifact, and route-fallback verification before describing a deployment as production-ready. Never put secrets in `VITE_*` variables because frontend values are browser-visible.
